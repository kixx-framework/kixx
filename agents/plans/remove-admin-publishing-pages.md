Remove Admin Publishing Pages
=============================

Remove the read-only admin panel pages under `/admin/publishing` (the overview at `/admin/publishing`, `/admin/publishing/builds/:buildId`, and `/admin/publishing/releases/:releaseId`), plus the routes, request handlers, nav link, dashboard card, and unit tests that exist only for them. After the change, requests to `/admin/publishing*` fall through to the admin catch-all route and return 404. The Publishing API (`/publishing-api/v1`), Publishing API token management (`/admin/publishing-api-tokens`), and admin file publish/unpublish stay exactly as they are.

Implementation Approach
-----------------------

### Decisions made with the operator

1. **Remove all three `/admin/publishing` pages.** Publishing is done entirely through the Publishing API, so the admin UI is unnecessary.
2. **Delete supporting code only if nothing else uses it.** Exploration found every supporting helper is shared with the Publishing API or other admin pages, so no helper is deleted. Do not delete or edit:
   - `lib/app/transaction-scripts/publishing/get-release.js`, `list-releases.js`, `list-activations.js` (imported by `lib/app/presentation/request-handlers/publishing-api/releases.js` and `builds.js`).
   - `lib/app/presentation/lib/pagination.js` (used by the Publishing API and other admin handlers).
   - `ContentAddressableStore#getBuildPointer` and `#listBuilds` in `lib/kixx/content-addressable-store/content-addressable-store.js` (used by `publishing-api/builds.js`).
   - The `urn:kixx:publishing:*` grants in `lib/app/permissions/roles.js`, and `docs/publishing-api.md`.
3. **Keep `/admin/publishing-api-tokens` and admin file publish/unpublish.** Token management and the `urn:kixx:publishing:files` resource (`FILE_RESOURCE` in `lib/routes/admin-panel.js`, used by `fileActionRoutes()`) are out of scope.
4. **No redirect.** `/admin/publishing*` should 404 through the existing catch-all, because nothing links there anymore. Verified: the `*` `static-pages` route at the end of `lib/routes/admin-panel.js` renders through `HyperviewPageHandler`, and `HyperviewService` throws `NotFoundError` when no page exists for the pathname (`lib/kixx/hyperview/hyperview-service.js` ~line 628 and ~656, covered by `lib/test/unit-tests/kixx/hyperview/hyperview-service.test.js` "throws NotFoundError when no page is published at the pathname"). Deleting `lib/pages/admin/publishing/` is therefore sufficient for the 404.

### Cross-cutting constraints

- Do not change any file under `lib/app/presentation/request-handlers/publishing-api/`, `lib/routes/publishing-api-v1.js`, `lib/app/transaction-scripts/publishing/`, `lib/app/permissions/`, or `docs/`.
- Do not touch anything named `publishing-api-tokens` (pages, handlers, forms, nav entry, tests).
- Shared CSS classes used by the deleted pages (`card`, `callout`, `admin-content-section`, etc.) are used elsewhere; do not remove styles.
- `test-app/` copies of `lib/` code are git-ignored and regenerated by the test app builder; do not edit them.
- Use `git rm` for deletions so they are staged.
