Table Lists

A dense, scannable table of records with a status badge and per-row actions.

A table list lays out records in rows so their fields line up for comparison. The starter draws a hairline-ruled table inside a bordered wrapper that scrolls sideways on narrow screens, and pairs it with the status badge, a compact label for each record’s state.

When to use: a list of records that share several comparable fields — status, dates, sizes, owners — and carry per-row actions, such as files, invites, and API tokens. When not to: a few items with free-form content read better as Cards; a single record’s details belong in a definition list or form.

Anatomy

Eight parts. The table and its badges are static; links and buttons inside the rows carry their own states.

  1. Wrapper — .table-list, a hairline-bordered surface that scrolls sideways when the table is wider than the page. It is a focusable region (role="region", tabindex="0") with a focus ring.
  2. Caption — .table-list__caption names the list and is the region’s accessible name through aria-labelledby.
  3. Header row — <th scope="col"> cells in caption type, muted, over a strong rule.
  4. Row header — the <th scope="row"> that best identifies the record, usually a link to its detail page.
  5. Cells — dense --text-body-sm type with a hairline rule between rows. Text wraps, but cells keep a minimum width so the table scrolls rather than crushing text.
  6. Secondary line — a <div class="type-caption"> under the main value, such as the filename beneath a title.
  7. Status badge — .status-badge, the record’s state as a word with a tone marker.
  8. Actions cell — .table-list__actions holds a .cluster of links and small-button forms that never wraps. Actions stay quiet so the record’s fields lead the row.

Variants

The table has no modifiers. The status badge has a neutral default and four tone modifiers; each sets only the marker color from a semantic token.

Usage

Copy the wrapper, caption, and header pattern. Give each caption an id that is unique on the page and point the wrapper’s aria-labelledby at it.

<div class="table-list" role="region" tabindex="0" aria-labelledby="files-caption">
    <table class="table-list__table">
        <caption id="files-caption" class="table-list__caption">Files</caption>
        <thead>
            <tr>
                <th scope="col">Title</th>
                <th scope="col">Status</th>
                <th scope="col">Size</th>
                <th scope="col">Actions</th>
            </tr>
        </thead>
        <tbody>
            <tr>
                <th scope="row">
                    <a href="/admin/files/…">Quarterly report</a>
                    <div class="type-caption">q3-report.pdf</div>
                </th>
                <td><span class="status-badge status-badge--success">Published</span></td>
                <td>1.2 MB</td>
                <td class="table-list__actions">
                    <div class="cluster">
                        <a href="/admin/files/…">Manage</a>
                        <form method="POST" action="/admin/files/…/unpublish">
                            <button class="button button--small" type="submit">Unpublish</button>
                        </form>
                    </div>
                </td>
            </tr>
        </tbody>
    </table>
</div>

Accessibility

  • The wrapper is a scroll container, so keyboard users must be able to reach it: keep role="region", tabindex="0", and aria-labelledby pointing at the caption. The region and the table share the caption as their name.
  • Every table has a visible <caption> that names the list.
  • Put scope="col" on column headers and scope="row" on the cell that identifies the record, so screen readers announce each cell with its column and row.
  • The badge text carries the status; the marker color only reinforces it. Never show a badge without a word.
  • Repeated action labels (“Manage”, “Revoke”) take their row context from the row header. Keep labels short and make the row header meaningful.

Guidelines

Do

  • Use a table list when rows share fields worth comparing down a column.
  • Lead each row with the field people scan for, as a row header.
  • Show status with a badge whose text is the status word.
  • Make row actions links whenever they navigate, such as “Manage” or “View”.
  • Use a .button--small inside a form only when the action changes data, such as “Publish” or “Revoke”. Add .button--secondary to make it recede further.

Don’t

  • Drop the caption, the region role, or tabindex from the wrapper.
  • Add row hover, zebra stripes, or a stacked mobile layout — the wrapper scrolls instead.
  • Color the badge text or the row; tone belongs to the marker.
  • Use a table for a handful of free-form items; reach for cards.
  • Put full-size buttons in a row — they crowd out the data the row exists to show.
