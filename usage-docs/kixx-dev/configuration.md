# Configuration

How `kixx-dev` finds your project, which project versions it supports, and
where its settings live.

## How a project is found

A Kixx project is a directory that holds `kixx/plugin.json`: the manifest of
the Kixx core your project carries in its `kixx/` directory.

A command that needs a project starts at the directory you pass as its last
argument, or at the working directory when you pass none. It then walks up,
one directory at a time, and uses the first directory that holds
`kixx/plugin.json`. So you can run a command anywhere inside your project:

```sh
cd my-site/pages/blog
kixx-dev generate          # works on my-site
kixx-dev generate ~/my-site
```

When no directory at or above the start holds `kixx/plugin.json`, the
command prints where it looked and exits `3`.

A project needs no `.kixx/` directory to be found.

## Supported project versions

`kixx-dev` reads the `version` in your project's `kixx/plugin.json` before
it does anything else in the project.

- **Kixx 7.0.0 and later 7.x versions are supported.** A prerelease tag is
  ignored, so `7.0.0-alpha.0` counts as `7.0.0`.
- **Another major version is refused.** The command exits `3` and tells you
  which `kixx-dev` to install, or to upgrade the project's Kixx.
- **A project newer than your `kixx-dev`, in the same major version, still
  runs.** One line on stderr tells you so. Upgrade `kixx-dev` if something
  fails.
- A `kixx/plugin.json` that is not JSON, or has no version, also exits `3`.

## Your project's own Kixx does the work

`kixx-dev` holds no copy of the framework's logic. When a command needs it,
`kixx-dev` loads it from your project's `kixx/` directory:

- `kixx-dev generate` runs your project's generator.
- `kixx-dev local create` reads `example.env.secrets` with your project's
  parser.

That is why one `kixx-dev` works with every supported project version, and
why what it writes is what your project's Kixx expects.

`kixx-dev` never loads your `app/` code, your plugins, or your entry points
into its own process. `kixx-dev dev` and `kixx-dev local start` run your
app's `node-server.js` in a separate process; see [dev.md](dev.md#runtimes).

If a file `kixx-dev` needs is missing from your project's `kixx/`, the
command exits `3` and names the file. Restore the `kixx/` directory.

## Settings: the two `.kixx` layers

Settings live in a `.kixx` directory in two places: your home directory and
your project's directory.

```
~/.kixx/config.json             <- home layer, settings
~/.kixx/secrets.json            <- home layer, secrets
<project>/.kixx/config.json     <- project layer, settings
<project>/.kixx/secrets.json    <- project layer, secrets
```

The project layer is merged over the home layer. Write a shared value once
in `~/.kixx`, and put only what differs in each project. A `null` in the
project layer cancels the value from the home layer.

- A missing directory or file is an empty layer.
- A file that exists but is not a JSON object is a usage error (exit `2`)
  that names the file.
- Secret values go in `secrets.json`, never in `config.json` or any other
  file git tracks. Never commit `secrets.json`: add `.kixx/secrets.json` to
  your `.gitignore`.

**No command in this version reads a setting.** The files are loaded and
checked for every command that needs a project, so a broken file is reported
early. The commands that publish, deploy, and manage a site will read their
origins and credentials from here; each one's page will list its keys when
the command is built.

`.kixx/` also holds data that `kixx-dev` writes. Local instances live in
`<project>/.kixx/instances/` by default; see [local.md](local.md).

## Project files `kixx-dev` reads

| File | Read by | Notes |
| --- | --- | --- |
| `kixx/plugin.json` | every command that needs a project | Finds the project and gives its version. |
| `kixx/plugin.json`, each `plugins/<name>/plugin.json`, `app/app.json` | `generate` | The manifests. Read by your project's generator. |
| `example.env.secrets` | `local create` | Generated by `generate`. Lists the secret names your app needs. |
| `example.env` | `local create` | The starting point of an instance's `.env`. |
| `node-server.js` | `dev`, `local create`, `local start` | The entry point `kixx-dev` runs your app through. |

`example.env.secrets` holds names, never values. A plain `NAME=` line is a
required secret. A line after `# @optional` is optional. A line after
`# @required-outside-development` is required in every environment except
`development`. It is generated, so change a manifest and run
`kixx-dev generate`; don't edit it.

`kixx-dev` never prints a secret value. An error about a secrets file names
the file, never a line's text.
