Design Aesthetic

Kixx ships a blank canvas. What follows is a default, not a brand.

Kixx is a starter framework. What ships in this repository is meant to be built on, so the default frontend is deliberately neutral, accessible, and easy to override — not a house style you fight to remove. A downstream site is expected to reskin the visible defaults; it is not expected to rewrite the structure underneath them.

That split — structure you keep, look you change — is the organizing idea for the rest of this guide. The sections below spell it out: what is fixed, what is a default, and the accessibility floor that applies either way.

What is fixed

These are structural rules, not aesthetic choices. A downstream site keeps them even after it changes every token and modifier.

  • Semantic HTML first — reach for the right element before reaching for a class. A heading is a heading; a button performs an action, a link navigates.
  • BEM ownership — a block owns its elements and its internal layout, never its own outside margin. An element is only ever styled from inside its own block’s rules.
  • Flow spacing — vertical rhythm between siblings is owned by the parent .flow, not by the component. See Layout for the full contract.
  • Composition — page structure is layout primitives → blocks → elements, in that order of responsibility. A layout class never carries block styling; a block never lays out its siblings.
  • Tokens before literals — a component rule reads a semantic --color-* token, never a raw --palette-* value or a color literal.
  • No inline styles — ever. Resolve styling through an existing component, a shared stylesheet, or a page-local page_stylesheet include.

What is a default

Everything below is a starting value, chosen to be inoffensive and get out of the way — not a rule to defend. Change it through a token first, a modifier second.

  • A generic system sans-serif — no downloaded font files. Change it by overriding --font-body / --font-display in your own base template.
  • The palette — a warm-paper-and-near-black-ink base with one link accent and a status family. Change it in the --palette-* tier; see Colors.
  • A small corner radius — 0.25rem on buttons, fields, cards, and callouts, all sharing --control-radius / --radius-md. Change the token to go square or pill-shaped.
  • Hairline borders, no shadows — depth comes from a 1px rule, never a drop shadow. Add shadows in your own stylesheet if your design calls for them.
  • Hover inversion — buttons and similar controls flip fill and text color on hover rather than shifting a shadow or scale. Add a new modifier if you want a different interaction language.
  • A single link accent — one color for links, focus rings, and code, so color stays a signal. Add more only as new status tokens, not decoration.

Accessibility floor

These are not optional, in the default theme or in anything built on top of it.

  • Visible focus — every interactive control shows a --color-focus-outline ring on keyboard focus (:focus-visible), never removed.
  • Comfortable targets — buttons and fields hold at least a 2.5rem minimum dimension (WCAG 2.5.8).
  • Token contrast — text and status tokens are tuned to hold AA contrast on both color schemes; don’t recolor body text to a status hue tuned for a 3:1 mark.
  • Native controls stay native — select, checkboxes, radios, file inputs, and range inputs keep their platform affordance. Only text-like inputs and textarea get a custom box.
  • Zoom-safe type — shared roles use fixed rem steps (WCAG 1.4.4); fluid clamp() sizing is reserved for bounded, page-local display type and always keeps a rem floor and ceiling.

Guidelines

Do

  • Treat every color, radius, and spacing value here as a starting point for your own site.
  • Change a default through its token first, a new modifier second.
  • Keep the structural rules — BEM ownership, flow spacing, composition — even after restyling everything else.
  • Preserve focus rings, target sizes, and native control behavior no matter how far you take the visual redesign.

Avoid

  • Treating the shipped look as a brand to protect — it is a placeholder.
  • Reaching for a one-off inline override instead of a token or modifier.
  • Restyling a shared block’s elements from a page-local stylesheet.
  • Removing a focus ring, shrinking a target below the floor, or styling a native control’s internals.
